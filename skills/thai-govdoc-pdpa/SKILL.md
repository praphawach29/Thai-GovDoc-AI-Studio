# Thai GovDoc PDPA — ข้อมูลส่วนบุคคลและการส่งข้อมูลให้ AI

ใช้คู่กับ `AGENTS.md` (กฎเหล็ก) และ `skills/thai-govdoc-ai-drafting` (pipeline ทั้งหมด) — ถ้าขัดกัน `AGENTS.md` ชนะ
สิ่งที่เขียนในนี้เป็นแนวปฏิบัติทางเทคนิค ไม่ใช่ความเห็นทางกฎหมาย การตัดสินสุดท้ายเป็นของเจ้าหน้าที่คุ้มครองข้อมูลส่วนบุคคล (DPO) ของหน่วยงาน

## 1. ใช้ skill นี้เมื่อไหร่

- เพิ่มหรือแก้จุดใดก็ตามที่ส่งข้อความ/ภาพไปให้ Gemini หรือ Claude
- แก้หรือเพิ่มรูปแบบข้อมูลที่ต้องปิด (ชื่อ เลขบัตร โทรศัพท์ ฯลฯ) หรือพบว่า AI ร่างชื่อผิด/หาย
- ผู้ใช้ถามว่า "แบบนี้ผิด PDPA ไหม" หรือจะเปิดให้คนในหน่วยงานใช้เอกสารจริง
- เตรียมเอกสารประกอบให้ DPO / ผู้บริหารอนุมัตินำร่อง

## 2. หลักกฎหมายที่เกี่ยวข้อง (สรุปสำหรับนักพัฒนา)

| ประเด็น | พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล พ.ศ. ๒๕๖๒ | ผลต่อระบบ |
|---|---|---|
| ฐานการประมวลผล | ม. 24 (4) ปฏิบัติหน้าที่/ใช้อำนาจรัฐ — งานสารบรรณปกติไม่ต้องขอความยินยอม | ใส่ชื่อบุคคลในหนังสือราชการได้ตามปกติ |
| ข้อมูลอ่อนไหว | ม. 26 สุขภาพ ประวัติอาชญากรรม ศาสนา ความพิการ ข้อมูลชีวภาพ ฯลฯ เงื่อนไขเข้มกว่า | เรื่องวินัย ร้องเรียน ใบรับรองแพทย์ ต้องระวังเป็นพิเศษ |
| ผู้ประมวลผลข้อมูล | ม. 40 ผู้ให้บริการ AI/คลาวด์ต้องทำตามข้อตกลงกับหน่วยงาน | ใช้ API แบบเสียเงินที่ไม่นำข้อมูลไปเทรน เก็บหลักฐานเงื่อนไขไว้ |
| ส่งข้อมูลออกนอกประเทศ | ม. 28–29 ปลายทางต้องมีมาตรฐานเพียงพอหรือมีมาตรการคุ้มครองที่เหมาะสม | Supabase/Vercel อยู่สิงคโปร์, Gemini/Claude อยู่ต่างประเทศ |
| ความมั่นคงปลอดภัย | ม. 37 มาตรการรักษาความปลอดภัย, แจ้งเหตุละเมิดภายใน 72 ชม. | RLS ตาม `org_id`, audit chain, ปิดข้อมูลก่อนส่ง AI |
| เอกสารชั้นความลับ | ระเบียบว่าด้วยการรักษาความลับของทางราชการ (ไม่ใช่แค่ PDPA) | ห้ามส่งให้ AI ภายนอกเลย (`core/security.cloud_ai_allowed`) |

## 3. ข้อมูลออกจากระบบไปที่ไหนบ้าง

| จุด | ไฟล์ | ส่งอะไร | ปิดข้อมูลส่วนบุคคล? |
|---|---|---|---|
| เก็บไฟล์ต้นเรื่อง/ร่าง | `server/supabase.py`, Storage bucket `sources` | ไฟล์ทั้งฉบับ | ไม่ (เก็บใน Supabase สิงคโปร์ แยกตาม RLS) |
| AI อ่านไฟล์สแกน (OCR) | `core/llm_drafter.ocr_images_with_llm` | **ภาพหน้าเอกสารทั้งหน้า** | **ไม่ได้** — ภาพปิดข้อมูลไม่ได้ก่อนอ่าน |
| AI ร่างเนื้อความ | `core/llm_drafter.draft_content_with_llm` | คำสั่งผู้ใช้ + ข้อความต้นเรื่อง + ตัวอย่างสำนวน | **ปิด** (`PiiVault`) — ตัวอย่างสำนวนปิดด้วย `mask_facts` อยู่แล้ว |
| AI เสนอข้อกฎหมาย | `core/llm_drafter.structured_call` ← `server/routers/legal.py` | ข้อความเรื่องที่ร่าง + ตัวบทกฎหมาย | **ปิด** (`structured_call` ปิดทุก prompt) |
| AI อ่านไฟล์กฎหมายสแกน | `server/routers/legal_import.py` | ภาพหน้ากฎหมาย | ไม่ต้อง (ตัวบทกฎหมายเป็นข้อมูลสาธารณะ) |

ข้อจำกัดที่ต้องบอกผู้ใช้ตรง ๆ: **ไฟล์สแกน/ภาพถ่ายถูกส่งให้ AI อ่านทั้งภาพ** ระบบปิดข้อมูลได้เฉพาะขั้นร่าง (หลังได้ข้อความแล้ว)
ไฟล์ PDF ที่มีข้อความฝังอยู่ (ไม่ใช่สแกน) ไม่ผ่าน OCR จึงไม่ถูกส่งให้ AI ทั้งฉบับ

## 4. การปิดข้อมูลก่อนส่ง AI (`core/pii_mask.py`)

```python
from core.pii_mask import PiiVault
vault = PiiVault()
masked = vault.mask("นายสมชาย ใจดี โทร 081-234-5678")   # "[ชื่อ_1] โทร [โทร_1]"
... ส่ง masked ให้ AI ...
vault.unmask(ai_text)                                   # ใส่ค่าจริงกลับ
vault.summary()                                         # "ชื่อ 1 · โทรศัพท์ 1"
```

**ที่ปิด** (รหัส `[ชนิด_ลำดับ]`, ค่าเดียวกันได้รหัสเดิมทั้งเอกสาร):

| รหัส | ข้อมูล | หมายเหตุ |
|---|---|---|
| `[ชื่อ_N]` | คำนำหน้า + ชื่อ (+ นามสกุล), ชื่อในวงเล็บใต้ลายมือชื่อ | ไม่ปิด "นายกรัฐมนตรี/นายอำเภอ/นายทะเบียน..." (รายการยกเว้นใน `_NAME_RX`) |
| `[เลขบัตร_N]` | เลขประจำตัวประชาชน ๑๓ หลัก (มี/ไม่มีขีด, เลขไทย/อารบิก) | ไม่ตรวจ checksum เพราะ OCR อาจผิดหลัก |
| `[โทร_N]` | โทรศัพท์ที่ขึ้นต้นด้วย 0 หรือ +66 | รวมเบอร์สำนักงาน (ปิดไว้ก่อนไม่เสียหาย เพราะใส่กลับครบ) |
| `[อีเมล_N]` | อีเมล | |
| `[บัญชี_N]` | เลขบัญชีธนาคารที่มีคำว่า "บัญชี" นำหน้า | |
| `[ที่อยู่_N]` | "บ้านเลขที่ ... หมู่ที่ ..." | คงตำบล/อำเภอ/จังหวัดไว้ (AI ต้องใช้บอกสถานที่จัดงาน) |

**ที่ไม่ปิด (ตั้งใจ):** ชื่อหน่วยงาน ตำแหน่ง วันที่ จำนวนเงิน เลขที่หนังสือ — AI ต้องใช้ร่าง และ `fact_check` ใช้ตรวจกับต้นเรื่อง

**การใส่ค่าจริงกลับ (`unmask`)** ทนต่อการที่ AI เปลี่ยนรูปรหัส: `[ชื่อ_๑]`, `[ชื่อ 1]`, `[ ชื่อ_1 ]` ใช้ได้หมด
- ถ้า AI เขียนคำนำหน้าซ้ำ เช่น `นาย[ชื่อ_1]` ระบบตัดคำนำหน้าที่ซ้ำออก
- รหัสที่ไม่มีในต้นเรื่อง (AI แต่งขึ้น) กลายเป็น `[✏️ ระบุชื่อ]` ฯลฯ ให้ผู้ใช้กรอก — ห้ามปล่อยรหัสดิบถึงผู้ใช้
- `SYSTEM_PROMPT` ข้อ 10 บอก AI ให้คัดลอกรหัสตรงตัว ห้ามเดาค่าจริง

**เปิด/ปิด:** `LLMConfig.mask_pii` (ค่าเริ่มต้นเปิด) ← env `GOVDOC_MASK_PII` (`0` = ปิด ใช้เฉพาะไล่ปัญหา) ใน `server/settings.py`
ขั้นตอนในหน้าจอบอกจำนวนที่ปิด เช่น "ปิดข้อมูลส่วนบุคคลก่อนส่ง AI: ชื่อ 2 · โทรศัพท์ 1"

## 5. กฎเมื่อเพิ่มจุดเรียก AI ใหม่

1. ตรวจชั้นความลับก่อนเสมอ (`cloud_ai_allowed(secret)`) — ไม่ทราบชั้น = ไม่ส่ง (fail-closed)
2. ข้อความที่มาจากเอกสารผู้ใช้ต้องผ่าน `PiiVault.mask` ก่อน และ `unmask` ทุกช่องข้อความในคำตอบ
   ใช้ `structured_call` (ปิดให้อัตโนมัติ) แทนการเรียก SDK เองถ้าทำได้
3. ห้าม log เนื้อหาเอกสาร/prompt (ดู `_log_failure` — log เฉพาะชนิด error และสถานะ)
4. ภาพเอกสารปิดข้อมูลไม่ได้ — ถ้าจะส่งภาพใหม่ ต้องเขียนในตารางหัวข้อ 3 และบอกผู้ใช้
5. เพิ่มเทสต์ใน `tests/test_step23_pii_mask.py`: prompt ที่ส่งจริงต้องไม่มีชื่อ/เลข และคำตอบที่ได้ต้องมีค่าจริงกลับมา

## 6. รายการเตรียมก่อนเปิดนำร่องกับเอกสารจริง

- [ ] DPO ของหน่วยงานรับรองการใช้งาน (ส่งตารางหัวข้อ 3 + 4 ให้ดู)
- [ ] ใช้ API key แบบเสียเงินของ Gemini/Claude ที่ระบุว่าไม่นำข้อมูลไปเทรน เก็บหลักฐานเงื่อนไขการให้บริการ
- [ ] ประกาศความเป็นส่วนตัวให้ผู้ใช้นำร่องอ่าน: เก็บอะไร ส่งให้ใคร เก็บนานเท่าไร
- [ ] กำหนดระยะเวลาเก็บไฟล์ต้นเรื่อง (มีถังขยะ + ลบถาวรแล้ว: migration 9/11 — ยังไม่มีลบอัตโนมัติตามอายุ)
- [ ] แจ้งผู้ใช้: ห้ามใช้กับเอกสารชั้นลับขึ้นไป และเรื่องที่มีข้อมูลอ่อนไหว (สุขภาพ วินัย คดี) ให้ใช้ PDF ข้อความหรือพิมพ์เอง ไม่ใช้ไฟล์สแกน
- [ ] ขั้นต่อไป (ยังไม่ได้ทำ): ตัวเลือก "ไม่ใช้ AI อ่านไฟล์สแกน" ต่อเอกสาร, ลบไฟล์ต้นเรื่องอัตโนมัติตามอายุ, ตรวจจับข้อมูลอ่อนไหวแล้วเตือนก่อนส่ง

## 7. ข้อผิดพลาดที่ต้องระวัง

| อาการ | สาเหตุ | ทางแก้ |
|---|---|---|
| "นายกรัฐมนตรี ได้..." กลายเป็น `[ชื่อ_1]` | คำที่ขึ้นต้นด้วย นาย/นาง แต่ไม่ใช่ชื่อ | เพิ่มคำใน negative lookahead ของ `_NAME_RX` + เทสต์ |
| ชื่อกินคำถัดไป เช่น "นางสาวสมหญิง ขอลาป่วย" | นามสกุลเป็นตัวเลือก จับคำถัดไปเป็นนามสกุล | คำต้องห้ามเป็นนามสกุลใน `_NOT_SURNAME` |
| ร่างมี `[ชื่อ_1]` ค้าง | AI เปลี่ยนรูปรหัสแบบที่ regex ไม่รู้จัก | ขยาย `_TOKEN_RX` แล้วเพิ่มเทสต์รูปแบบนั้น |
| ร่างมี "นายนายสมชาย" | AI ใส่คำนำหน้าหน้ารหัส | `unmask` ตัดคำนำหน้าซ้ำ — ถ้ายังเกิด ดูรายการคำนำหน้าใน `_TITLES` |
